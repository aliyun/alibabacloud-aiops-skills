# 验收标准

## 功能验收

- [ ] 能识别“手机号中间四位打星”“身份证保留首尾”“邮箱脱敏”“动态脱敏”“白名单绕过”等自然语言意图。
- [ ] 能提示当前公开 `dataphin-public` CLI 未暴露脱敏规则 CRUD / 白名单 / 默认配置命令。
- [ ] 能使用 `list-security-identify-results` 查询目标字段是否已有安全识别结果。
- [ ] 能使用 `list-security-identify-records` 精确确认 `table-catalog`、`table-name`、`field-name` 与分类状态。
- [ ] 能使用 `get-security-classify` 回读分类与分级绑定关系。
- [ ] 当字段未打标时，能提示先完成字段分类分级，再继续脱敏需求交付。
- [ ] 能输出完整脱敏需求清单：目标字段、分类 ID、算法、作用场景、作用范围、白名单、验证方式。

## 安全验收

- [ ] 不伪造 `create-desensitize-rule`、`update-desensitize-rule`、`delete-desensitize-rule` 等不存在的公开 CLI 命令。
- [ ] 不直接调用页面内部 `/api/datasecurity/desensitization/...` REST。
- [ ] 不默认使用全业务板块、全项目、全表范围。
- [ ] 白名单必须确认账号、场景和生效日期，不能默认长期有效。
- [ ] 默认脱敏配置属于租户级全局设置，当前 Skill 不执行写入。
- [ ] 任何未来写操作都必须先 HITL 确认命令全文、影响范围和回滚方案。

## 业务语义验收

- [ ] 清楚区分“字段已分类分级”和“查询已脱敏”两个状态。
- [ ] 能说明脱敏规则通常依赖分类或分级，但分类分级本身不会改变查询结果。
- [ ] 能说明白名单是绕过脱敏的例外规则，不是普通权限授权。
- [ ] 能说明即席查询、读写开发、资产展示等场景可能有不同脱敏生效口径。
- [ ] 能说明脱敏效果验证需要实际查询结果与原始明文对比。

## 测试验收

- [ ] L1 子 Skill 静态检查通过。
- [ ] L1 父套件静态检查通过。
- [ ] L2 确认公开命令集与版本感知 OpenAPI 索引无脱敏规则 CRUD。
- [ ] L2 公开前置检查命令 dry-run 或真实只读验证通过。
- [ ] L3 poc 只读验证能查询现有字段分类分级标签或明确返回无标签。
- [ ] 测试报告必须同步到 Aone 开发任务正文后再修改工单状态。
