## v4.4.1 (2026-08-28) — Agent Behaviour Hardening (no script logic changes)
- **New "Command Invocation Convention (MUST)" section in `SKILL.md`**: the review must be issued as a single direct shell command in the canonical form `python3 scripts/cutover_reviewer.py <manual path> --scenario <full|batch|other> [...]`. The interpreter must be `python3`, the script must be referenced through the relative path from the skill root, and absolute paths, shell variables (`$SKILL_DIR/...`), command substitution and generated `.sh` wrappers are forbidden. Argument order is fixed: manual path first, then `--scenario` / `--list-sheets`, then optional flags.
- **Sheet inspection is script-only**: obtaining Sheet names through an inline `python3 -c` / `openpyxl` / `pandas` snippet is forbidden; use `--list-sheets`.
- **Sheet names supplied by the user are used verbatim**: the first run passes exactly the strings the user gave to `--process-sheet` / `--rollback-sheet`, even when auto-recognition reports different names; any fallback warning is reported back to the user instead of being silently corrected.
- **Non-blocking list-then-confirm flow**: when the user wants an explicit mapping but does not know the Sheet names, only `--list-sheets` runs and the turn ends with the confirmation question; running the review in the same turn is a violation. The script never reads stdin, so the Agent must never wait, sleep or poll, and must never leave a turn unanswered.
- **New "Final Answer Requirements (MUST)" section**: the answer opens with a one-line execution summary carrying the manual path, the scenario as both the CLI value and words, the `Sheet` mapping actually reviewed (plus any extra dimensions named by the user), the report path, the score, the risk level and the CRITICAL count — before the per-risk list. The termination checklist was renumbered accordingly.
- **Tool-budget hard stop**: on reaching the call budget the Agent answers from the evidence already collected; identical retries and idle loops are forbidden.
- **`references/usage-guide.md`**: cheat-sheet examples normalised from `python` to `python3`, a `--list-sheets` example added, and the invocation convention restated.

## v4.4 (2026-08-24) — Issue Aggregation + Conditional Suppression
- **Added issue-aggregation layer `ISSUE_TOPICS`** (`scripts/config.py`): multiple check-item hits of the same underlying risk are merged into one entry, taking the highest severity within the group, and echoing the original hit items with "hit checks: N (…)" at the end of the entry. The 0820 baseline risk entries were compressed from 44 to 16.
  - `ISSUE_TOPICS` is **order-sensitive** (first hit wins): `topic_redis` / `topic_aliyun_db` must precede `topic_src_readonly`, which contains the bare keyword "read-only", otherwise they would be grabbed by the generic topic.
  - The `core` of `topic_process_consistency` is set to `True`, consistent with its underlying CRITICAL rating, avoiding the contradiction of a "fatal" entry landing in the "improvement suggestions" section.
- **Topic matching changed to short identifier phrases**: added `_issue_key_phrase()` (the content inside `[square brackets]`, otherwise the first sentence); `_match_topic(category, key_phrase)` no longer matches on the full message containing a lengthy `check_logic`. This fixes the **topic-bleed** defects where "maintenance notice" swallowed "traffic recovery plan" and "traffic switching" swallowed rollback decision / source read-only.
- **Added conditional suppression `SUPPRESSION_RULES`**: when a `when_any` keyword hits the full text of the Sheets actually under review, the reminders matched by `only_messages_any` are suppressed. Two rules configured: (1) the manual contains "Alibaba Cloud application startup" → exempt the group of reminders "Alibaba Cloud database read-only in advance / restore read-write during cutover" (the target-side application is shut down before the cutover, so there is no risk of being written dirty in advance); (2) the manual contains an application/service startup action → exempt the keyword-based false positive of "missing service restart node". The appendix echoes it as "N item(s) exempted — <reason>" (previously the wrong use of `note['message']` rendered an empty strikethrough; changed to `count` + `reason`).
- **Cap on key items to confirm `MAX_MUST_CONFIRM_ITEMS = 10`**: only topics with `core: True` and severity CRITICAL/HIGH enter "I. Key Items to Confirm", truncated; the rest fall into "II. Items to Note". 0820 baseline: 10 key / 6 note.
- **`CATEGORY_PREFIX_REWRITE`**: in the full scenario, "Batch Cutover-" is uniformly rewritten as "General Cutover-", to avoid users misjudging that the scenario was misidentified.
- **Wording optimization**: the rollback-decision entry suggestion changed to "list a dedicated section of rollback decision basis (do not mix it into the operation-step table)", providing two suggested decision points (before traffic is officially forwarded, before DNS switch).

## v3.3 (2026-06-10) — Review-Dimension Enhancement
- **Added 8 batch-cutover checks (batch_1_11 ~ batch_1_18)**:
  - `batch_1_11` Kafka/message-middleware consumption confirmation — stopping traffic does not necessarily stop consumption; watch passive message sources such as scheduled jobs
  - `batch_1_12` scheduled-job stop method and time cost — one-by-one clicking vs batch operation, with a large difference in estimated time
  - `batch_1_13` target-side initial-state pre-statement — MySQL/Redis initial read-only, whitelist risk, application state
  - `batch_1_14` service restart strategy — total number of services, base services first, two-phase startup (single Pod first, then scale-out)
  - `batch_1_15` estimated time cost of cutover steps — every operation step must have an estimated-time-cost field
  - `batch_1_16` Nginx/proxy-layer config-change standard — the full flow of backup → overwrite → reload
  - `batch_1_17` big-data consumption-link cutover — Kafka consumption stop/recover, Flink jobs, message-backlog check
  - `batch_1_18` process-consistency check — stop/recover steps correspond, DNS-switch-timing reasonableness
- **Added 2 full-cutover checks (full_2_5 ~ full_2_6)**:
  - `full_2_5` maintenance-notice mounting method and traffic interception — WeChat mini-program vs Alipay vs Nginx, the method must be clear
  - `full_2_6` structured rollback decision conditions — independent of operation steps, two key decision points
- **Updated CRITICAL_CHECKLIST_ITEMS**: added Kafka consumption confirmation, target-side initial state, service restart strategy, process consistency
- **Updated CRITICAL_PROCESS_NODES**: added Kafka consumption confirmation/stop, scheduled-job stop, Nginx config change, service restart
