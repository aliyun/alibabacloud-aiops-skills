# CMS 2.0 SPL umodel Query Reference

The LoongSuit side reads trajectories via CMS 2.0 **Unified Data Model (UModel)**'s `GetEntityStoreData`. The query language is
**SPL in umodel mode**. Official documentation only provides examples for `.umodel` metadata queries; the trace query syntax in this document was **discovered through practical testing**
and is hardened by the generator functions in `cms_trace.py`.

## 1. CLI Invocation Pattern

```bash
aliyun cms get-entity-store-data --api-version 2024-03-30 \
  --workspace <workspace name> --from <unix seconds> --to <unix seconds> --query <SPL> \
  --region <region> --user-agent <UA>

aliyun cms list-workspaces --api-version 2024-03-30 \
  --biz-region <region> [--workspace-name-list <name> ...]
```

- **Must include `--api-version 2024-03-30`**: CMS 2.0 APIs are not in the default 2019-01-01 version; omitting it will report
  `This command is not available in the current API version`.
- Requires the `aliyun-cli-cms` plugin (its description is "multi-version API support").
- `--workspace` is a **real query parameter**, not a decorative label.

## 2. Dataset (Trace Set)

Discovered via `.umodel | where kind = 'trace_set'`; the trajectory dataset is:

| Item                                                                       | Value                                              |
| -------------------------------------------------------------------------- | -------------------------------------------------- |
| domain                                                                     | `apm`                                              |
| name                                                                       | `apm.trace.common`                                 |
| protocol                                                                   | `otel`                                             |
| common_schema                                                              | `apm-common` v0.1.16                               |
| `trace_id_field` / `span_id_field` / `parent_span_id_field` / `time_field` | `traceId` / `spanId` / `parentSpanId` / `__time__` |

Spec-declared fields: `traceId` / `spanId` / `parentSpanId` / `serviceName` / `spanName` / `kind` /
`hostname` / `startTime` / `endTime` / `duration` / `pid` / `statusCode` / `statusMessage` /
`traceState` / `resources` (json_object) / `attributes` (json_object) / `events` /
`resources.acs.arms.service.id`.

**Measured**: The returned rows are already in the downstream-shared span-row shape; `startTime`/`duration` are both in nanoseconds; `attributes` /
`resources` are JSON strings — so `cms_trace.cms_span_to_row()` is essentially a pass-through; no key name mapping is needed.

## 3. Syntax (Four Rules Discovered Through Testing)

### 3.1 Statements Must Start with a Directive

Bare index queries are rejected: `index query is not supported in umodel mode`. Available directives (enumerated from error messages):
`.LET` / `.SET` / `.PRINT` / `.TOPO` / `.ENTITY` / `.UMODEL` / `.UMODEL-COMMON-SCHEMA` / `.RUNBOOK` /
`.METRIC_SET` / `.LOG_SET` / `.TRACE_SET` / `.ENTITY_SET` / `.EVENT_SET` / `.RUNBOOK_SET` /
`.STOREVIEW` / `.LOGSTORE` / `.METRICSTORE` / `.EXTERNALSTORE` / `.RESOURCE`.

The trace query prelude (generated by `cms_trace.trace_set_prelude()`):

```
.trace_set with (domain='apm', name='apm.trace.common')
```

> Both `domain` and `name` are **required** in the `with` clause; providing only `name` will report
> `Invalid parameter 'domain or name'`. Writing `.trace_set('...')` or `with name='...'` is not accepted.

### 3.2 Attribute Keys Containing Dots Require Bracket Notation in JSONPath

```
json_extract_scalar(attributes, '$["gen_ai.session.id"]')
```

Dot notation `$.gen_ai.session.id` is parsed as a nested path (`gen_ai` -> `session` -> `id`); **measured to return all null**.
Generated by `cms_trace.attr(key)`.

### 3.3 Aggregation Must Use Alias Equals Form

```
| stats c = count(*) by serviceName        OK
| stats count(*) as c by serviceName       ERROR mismatched input 'c'
| stats count(*) by serviceName            ERROR extraneous input 'serviceName'
| stats count() by serviceName             ERROR missing EQ at '('
```

Generated by `cms_trace.stats(alias, agg, by)`.

For **expression** aggregation, you must `extend` first:

```
| extend v = json_extract_scalar(attributes, '$["gen_ai.span.kind"]') | stats c = count(*) by v
```

Direct `stats c = count(*) by json_extract_scalar(...)` will error.

### 3.4 `statusCode` Type Inconsistency Requires Cast

```
| where cast(statusCode as bigint) = 2     OK
| where statusCode = 2                     ERROR eq(VARCHAR, INTEGER) not supported
| where statusCode = '2'                   ERROR '=' cannot be applied to bigint, varchar(1)
```

Generated by `cms_trace.status_error_pred()`. OTel semantics measured: `0`=UNSET (15198), `1`=OK (9),
**`2`=ERROR (115)**.

### 3.5 Other Verified Working Patterns

| Pattern            | Example                                                                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| String equality    | `\| where serviceName = 'qwenpaw'`                                                                                                       |
| Attribute equality | `\| where json_extract_scalar(attributes, '$["gen_ai.span.kind"]') = 'ENTRY'`                                                            |
| ID list            | `\| where traceId in ('<32hex>', '<32hex>')`                                                                                             |
| Projection         | `\| project traceId, spanId, parentSpanId, spanName, serviceName, startTime, duration, statusCode, statusMessage, attributes, resources` |
| Sorting            | `\| sort startTime`                                                                                                                      |
| Pagination         | `\| limit <offset>, <count>` (also accepts `\| limit <count>`)                                                                           |

## 4. Pipe Command Inventory and Security Denylist

All available pipe commands enumerated from error messages:

`STATS`, `MAKE-SERIES`, `MAKE-TRACE`, `UNNEST`, `UNION`, `GRAPH-MATCH`, `GRAPH-CALL`, `MAKE-GRAPH`,
`PROM-CALL`, `ENTITY-CALL`, `SORT`, `LIMIT`, `WHERE`, `EXTEND`, `PROJECT`, `PROJECT-AWAY`,
`PROJECT-RENAME`, `PARSE-CSV`, `PARSE-JSON`, `PARSE-KV`, `PARSE-REGEXP`, `HTTP-CALL`, `LOOKUP`,
`EXPAND-VALUES`, `LOG-TO-METRIC`, `METRIC-TO-METRIC`, `PACK-FIELDS`, `SERIES-FORMAT`, `SERIES-STATS`,
`SERIES-UNNEST`, `SERIES-DRILLDOWN`, `RENDER`, `DEDUP-EXACT`, `DEDUP-FUZZY`, `DEDUP-SEMANTIC`,
`SEMANTIC-CLUSTER`, `SAMPLE`, `LLM-CALL`, `AGENTIC-CALL`, `EMBEDDING`, `JOIN`, `DYNAMIC-FILTER`,
`WINDOW`, `ELSE`, `IF`.

> **Read-only boundary**: Among these, **`HTTP-CALL` / `LLM-CALL` / `AGENTIC-CALL` / `EMBEDDING` / `ENTITY-CALL` /
> `PROM-CALL` / `GRAPH-CALL` initiate external HTTP or model calls** and do not belong to read-only observation.
> `cms_trace.SPL_DENY` intercepts these seven before any query goes out; a match triggers `ObsError("refused: ...")`.
> This is the same level of boundary as `sls_event._WRITE_VERBS` blocking SQL write verbs — **must not be relaxed**.

This skill also does not use `cms_natural_language_query` (it requires `CreateThread` / `CreateChat` write permissions).

## 5. `.umodel` Metadata Discovery (Official Documentation Caliber)

```
.umodel | limit 0, 10
.umodel | where kind = 'entity_set' | limit 0, 10
.umodel | where kind = 'trace_set'  | limit 0, 10
.umodel | where json_extract_scalar(metadata, '$.domain') = 'apm' | limit 0, 10
```

Returns a fixed five fields: `__type__` / `kind` / `metadata` / `schema` / `spec` (the last three are JSON strings, extracted with
`json_extract_scalar`). `spec` contains `fields` / `primary_key_fields` / `time_field`.

## 7. Relationship Between Workspaces and Projects (Measured)

- The CMS 2.0 workspace's own SLS project (named the same as the workspace, e.g., `default-cms-<uid>-<region>`) only has
  `__entity` / `__topo` logstores; **it does not contain traces**.
- Traces land in the `logstore-tracing` of projects like `proj-xtrace-<hash>-<region>` (description like
  `Managed by ARMS Service <workspace name>`).
- **But this skill does not read that SLS project directly**: it always retrieves data via `GetEntityStoreData` + `--workspace`, without composing
  project names. The binding (`--workspace`) **can only be provided by the user**; the skill has no auto-discovery mechanism.
