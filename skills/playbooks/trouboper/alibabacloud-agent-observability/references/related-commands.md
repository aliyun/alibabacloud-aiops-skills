## Scripts (All Read-Only; `--format json` is default and stable machine contract / `--format yaml` is isomorphic YAML; **no markdown option**)

| Script | Purpose | Key Parameters |
|---|---|---|
| `scripts/workflow.py` | **Canonical end-to-end entry point** for a complete user-facing analysis. Two subcommands: `search` (preflight → span_search → select → trace_chain → decision_evidence → report_render) and `trace` (preflight → trace_chain → decision_evidence → report_render). Persists every child JSON under `<run-dir>/facts/`, the HTML report under `<run-dir>/reports/html/`, and a manifest at `<run-dir>/workflow.json` recording each step's exit status / SHA-256 / the selected `trace_id`+`span_id` / report path+hash. Fail-fast on any child failure; manifest is structurally redacted before write (no credentials, no raw child output). **Use this instead of invoking child scripts by hand for a complete analysis** | Subcommand `search`: `--match` (required), `--limit` (default 50), `--select first\|unique` (required; `first` = hits[0] only when user explicitly asked for the first, `unique` = continue only when all hits share one trace_id), `--max-traces` (default 200). Subcommand `trace`: `--trace-id` (required). Common: `--region` (required), `--project` / `--workspace` (at least one), `--service-name`, `--mode`, `--from` / `--to` / `--hours`, `--run-dir` (default `reports/workflows/<sub>-<ts>-<id>`), `--format`. The component scripts below remain available as diagnostic building blocks |
| `scripts/preflight.py` | **Step 0.5 configuration preflight** (does not check data): seven checks `cli_version` / `plugins` / `credentials` (only outputs credential **type**, never outputs credential values) / `bindings` (at least one) / `sls_project` / `ebpf_logstore` / `cms_workspace`; unbound side set to `skipped` (valid configuration, not a failure). Item details see the preflight checks reference | `--region` (**required**), `--project`, `--workspace`, `--logstore`, `--strict` (exit code 2 on any fail), `--format`, `--no-cache`. **No time window parameters** |
| `scripts/trace_overview.py` | Time window overview aggregation (**LoongSuit**: call volume/error rate/latency/tokens/TTFT/loop candidates/cross-Agent services/`steps_from_span_kind`/`totals.trace_ids` top 50 for user to pick target trace; **eBPF**: process/container/host/network/HTTP composition, exchange latency, `genai_index_coverage`); `--compare-hours <N>` appends `drift` section (**LoongSuit side only**: computes same-caliber delta against the immediately preceding N-hour baseline window, `{base, current, delta_pct}`, baseline 0 gives delta_pct=None) | `--hours` (default 4h span), `--agent` (LoongSuit), `--max-traces` (default 200, outputs `enumeration_truncated` when hit), `--compare-hours`, eBPF narrowing parameters |
| `scripts/span_search.py` | **Content-based span locating** (LoongSuit only: ebpf-event has no message payloads): enumerates traces in window (ENTRY→LLM fallback), then client-side scans each span's `gen_ai.input.messages` **and** `gen_ai.output.messages` across all roles, hits output `hits[]` (`trace_id`/`span_id`/`op`/`field=input.<role>\|output.<role>`/`snippet`) — **a hit is an anchor**, `trace_id` feeds trace_chain, `span_id` feeds decision_evidence | `--match` (**required**, case-insensitive substring), `--limit` (default 50), `--max-traces` (default 200), `--hours` |
| `scripts/trace_chain.py` | **Chain reconstruction, analysis unit = single user-specified trace** (**LoongSuit**: parent-child tree, non-GenAI spans collapsed, includes `latency` (each chat's duration/TTFT/decoding/tokens/throughput + **trace self-baseline**), `context_growth` (input_tokens sequence + `ballooning_candidate`), `llm_analysis`/`tool_analysis`/`op_duration_split`; **eBPF**: exchange timeline with request/response paired by `http.exchange.id` + `patterns` (failed exchanges / 5xx / repeated calls / unpaired) + process facts, **window cannot be narrowed**). **All modes anchor on `--trace-id`** (both sources share the anchor, single-side no-data marks `present=false`, errors only when both are missing) | `--trace-id` (**required**), `--hours` (default 4h span), `--margin` (default 300s, trace boundary expansion), `--event-limit`, `--detail-limit` |
| `scripts/decision_evidence.py` | Evidence extraction (**LoongSuit**: target span messages/ancestor chain/siblings/react sequence/trace original task `entry_task`; **eBPF**: target runtime facts (HTTP/process/container/host/k8s) + three-ring context — same `http.exchange.id`, same `pid` ±60s, same `trace_id`; `messages`/`entry_task` always null) | `--span-id` (LoongSuit), `--event-id` (eBPF), `--trace-id` (LoongSuit direct: bypasses enumeration for traces without ENTRY spans), `--hours`, `--detail-limit`, `--list-limit` |
| `scripts/report_render.py` | **Step 5 HTML report rendering (template injection)**: maps trace facts to `window.TRACE_DATA = {meta, summary, spans}` and injects into `report-template.html` template (all sections rendered client-side by template, summary always `{}`); Agent analysis conclusions land on node note fields via `--spec`'s `notes{spanId}`; structural redaction + script block safe encoding + 4 self-checks before rendering (R1–R4, including monetary rejection). Common parameters (all analysis scripts): `--region` (**required**), `--project` (eBPF source) / `--workspace` (LoongSuit source) — **at least one, no environment variable fallback**, `--service-name` (**LoongSuit side only**: CMS `serviceName` filter; ebpf-event index has no `service.name`, that side always marks `service_filter_unavailable`), eBPF narrowing parameters `--agent-type` / `--comm` / `--container-id` / `--host` / `--event-name` / `--trace-id`, `--logstore` (default `ebpf-event`), `--mode both|loongsuit|ebpf` (**default both; automatically narrows when only one side is bound and outputs `mode_narrowed`**, legacy values `trace`/`event`/`auto` raise error on input), `--from` / `--to` (unix seconds), `--format json|yaml` (default json; **markdown has been removed**), `--no-cache`.

**Window and cache behavior** (performance optimization, tested):
- **Maximum window limit = window span (`to − from`) cap, not "how far back you can query"**: `AGENT_OBS_MAX_WINDOW_HOURS` (default 4) constrains single-query span, any historical ≤4h slice is valid. **No script reads or validates this variable**, exceeding the limit will just be very slow, won't be rejected — convergence relies on SKILL.md §8 Step 0 clarification discipline. **Explicit `--from/--to` recommended**: precise span (no grid pushing), and past slices hit permanent cache.
- Relative windows (`--hours`) have their end aligned upward to a 300s grid, start pushed forward by one additional grid: repeated runs within the same grid slot emit byte-identical queries, sharing cache. Explicit `--from/--to` is not aligned.
- Result cache is in system temp directory `agent_obs_cache/` (can be specified via `AGENT_OBS_CACHE_DIR`): entries whose window end exceeds 5 minutes are considered immutable and cached permanently; more recent entries expire per `AGENT_OBS_CACHE_TTL` (default 1800s). `list-log-stores` probing is also cached. `--hours` belongs to the recent window, repeated runs basically don't hit cache; iterative analysis with explicit `--from/--to` to past windows is what hits permanent cache.
- `trace_chain` output's `window_narrowed` indicates the actual scan window after narrowing (**trace boundary ± `--margin`**, boundary probed by `where traceId in ('<id>')` lightweight projection); **eBPF side is always null** (anchor fields are not indexed, cannot probe boundaries server-side), `window_narrowed_note` explains why — so eBPF side relies more on narrowing slices to control cost.
- **eBPF side** details are paginated at 100 rows/page with `--offset` (oldest first), per-logstore cap 2000 rows (`sls_event.EBPF_FETCH_CAP`), exceeding outputs `fetch_truncated: true` — **at this point all counts are samples, not full counts**.
- **LoongSuit side** details are fetched via `cms_trace.fetch_traces_spans` in batches of `traceId in (…)` (≤50 ids per batch) and deduplicated by `(traceId, spanId)`; enumeration (trace_overview / span_search) is capped by `--max-traces` (default 200), hitting the cap outputs `enumeration_truncated` sample marker. **Target trace is user-specified** (`--trace-id` direct, not affected by enumeration); when the user cannot provide a trace_id, `totals.trace_ids` is presented for selection, the skill does not select on behalf. **Traces with neither ENTRY nor LLM spans** will not appear in enumeration counts, but are visible via `trace_chain --trace-id` / `decision_evidence --trace-id` direct access; applications with no entry-layer instrumentation at all are covered by `kind=LLM` fallback and marked `enumeration_fallback: no-entry-span`.

## Report Output (HTML, Template Injection)

The observation report is delivered as a **self-contained single-file HTML**: trace facts are mapped to `TRACE_DATA` and injected into the template. Two steps: first persist the fact layer, then (optionally) write annotation spec and render.

```bash
python3 scripts/trace_overview.py <bindings> <slice> --format json > reports/facts/overview.json
python3 scripts/trace_chain.py  <bindings> <slice> --trace-id <id> --format json > reports/facts/chain.json
python3 scripts/report_render.py --facts chain=reports/facts/chain.json \
    [--spec reports/facts/notes.json] --out reports/html/<scenario>.html
```

- **`--facts` only needs `chain=trace_chain.py output`** (the fact layer for rendering); other facts
  are ignored and don't enter TRACE_DATA
- **`--spec` is the Agent-authored annotation layer**: `{schema_version: "obs-trace-report-v1",
  title?, notes: {spanId: text}}` — carries only text, no numbers, notes keys must be real
  spanIds in the trace (R2), analysis conclusions go here, anchoring is evidence
- **Template injection**: report body comes from `report-template.html` (`--template`
  can override); rendering replaces the example `window.TRACE_DATA` assignment and `<title>`
- **Self-containment is a tested guard**: after rendering, the artifact is scanned — external resources must be 0, `<script>` blocks must be exactly
  1 (template's built-in renderer), failing this refuses rendering; template must maintain zero external links, zero sensitive information
- **Redaction and encoding**: TRACE_DATA goes through structural redaction (private key blocks / AK patterns / `password=…`
  etc.) then `js_data_literal` script block safe encoding (`<`/`>`/`&` → `\uXXXX`), no string
  can escape the `<script>` block
- **Amounts**: spec layer monetary semantic text is mechanically rejected by R4; amounts are always "missing"
- **`--out -`** writes HTML to **stdout**, rendering summary to **stderr** — this is the only way tests
  can assert HTML content, it's an **intentional inversion**
- Output directory is auto-created; both `reports/facts/` and `reports/html/` are covered by `.gitignore`
- Contract and rules list see the rendering contract; scenario organization see
  the scenario playbooks; layman attribution categories see the attribution taxonomy

## Binding Parameters and Environment Variables

**Binding rules (CLI arguments or environment variables, CLI takes priority)**: `--region` **required**; `--project` (eBPF source: SLS project storing `ebpf-event`) and `--workspace` (LoongSuit source: CMS 2.0 workspace) **at least one**. When both are missing, the script errors at startup and lists all missing items at once. **Binding only one side is a valid configuration**: `sls_event.resolve_mode` returns `(mode, narrowed)` and automatically narrows to the bound source, the absent side is explicitly marked as a connectivity gap in the output (`sources.<name>.bound=false` + `gap`), **no silent degradation**; explicitly specifying `--mode` pointing to an unbound source raises an error.

**Value sources (can only be obtained from the user)**: Ask the user for the **SLS Project name** and **CMS 2.0 workspace name**, along with agent application name / region / trace time range / target trace trace_id (script see the clarification script). **The skill has no auto-discovery mechanism**, if the same environment binding already exists in conversation history it can be reused directly; if the user cannot provide them, explain the console navigation path in text for them to find it, **do not guess or concatenate resource names** (wrong names cause queries to silently return 0 rows, which is then misjudged as "no data in the window"). `--workspace` is a **real query parameter** for `GetEntityStoreData`, not a decorative label.

**Strongly recommended**: `--service-name` (agent application name) — **only takes effect on the LoongSuit side** (CMS SPL `serviceName = '<app-name>'` predicate). ebpf-event index **does not have** `service.name` nor `__tag__:__service_name__`, so eBPF side always sets `service_filter_unavailable: true` with a note (not an error). Values must be **copied verbatim from the console** (exact match, wrong names cause LoongSuit side to return 0 rows, this is not a connectivity gap). When omitted, queries all applications under the binding, output notes declare "not narrowed to a single application". eBPF side uses `--container-id` / `--host` / `--event-name` (indexed, server-side filtering) and `--agent-type` / `--comm` / `--trace-id` (not indexed, client-side filtering).

User-side navigation path (explain to user in text, don't send links): agent application name (= `--service-name`) is in **Cloud Monitor 2.0 console > target workspace > AI Agent Observability > AI Agent > AI Applications** list's "Application Name" column (the same table's "Region" column gives the region). CMS 2.0 workspace name is in the **Cloud Monitor 2.0 console** workspace list; SLS Project name is in the **Log Service console** project list (the one storing the `ebpf-event` logstore). (Source, for maintainer verification: `document_detail/3042596.html`)

**Environment variables (execution-side behavior only, unrelated to data source binding)**: `SKILL_SESSION_ID` (observation session identifier, for UA injection), `AGENT_OBS_NO_CACHE` (=1 disables result cache), `AGENT_OBS_CACHE_DIR` (cache directory), `AGENT_OBS_CACHE_TTL` (recent window cache expiry in seconds, default 1800), `AGENT_OBS_FETCH_WORKERS` (LoongSuit detail batch fetch concurrency, default 4; set to 1 to fall back to serial), `AGENT_OBS_MAX_WINDOW_HOURS` (maximum window limit = window span cap in hours, default 4; **for Agent clarification use, no script reads or validates it**, see SKILL.md §8 Step 0).
