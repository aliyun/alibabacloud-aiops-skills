# Normal Timeline Templates

Use a normal template when the user wants a reusable editing structure whose text or media changes between renders. A normal template is a parameterized Timeline stored by ICE (`AddTemplate`, `Type=Timeline`); it is different from the Type-2 custom snapshot templates (`17-snapshot-and-asr.md`).

## Workflow

1. Confirm the ICE region. Template creation is persistent, so describe the name, region, variable slots, and fixed assets before calling `AddTemplate`.
2. Write or generate the Config locally. This step is free and needs no output bucket.
3. Review the Config and create the template with `template_editor.py create --yes` only after user confirmation.
4. Call `get` and inspect `ClipsParam`; it is the contract callers must satisfy.
5. Run local `expand` with the intended `ClipsParam` and inspect the expected Timeline before spending a render. It writes the expansion, then exits non-zero for unsafe video-`LoopMode` spans; ICE still has no server-side dry-run.
6. Before rendering, confirm the same-region output bucket and the concrete replacements. If `expand` changes a parameter choice, restate the final mapping and whether the result trims or loops before asking for confirmation again. `submit` fetches and expands the template again, refuses an existing output object unless `--overwrite` is explicit, then submits. Poll and verify through the normal §8–§9 workflow.

```bash
# Offline starter Config
python "$SKILL_DIR/scripts/template_editor.py" generate \
  --preset video-concat -o template_config.json

# Persistent creation — only after the user reviewed the Config and slots (step 3). Type is always Timeline
python "$SKILL_DIR/scripts/template_editor.py" create \
  --name "Product Video Concatenation" --config template_config.json \
  --region cn-shanghai --yes

# Inspect Config and the generated ClipsParam schema
python "$SKILL_DIR/scripts/template_editor.py" get \
  --template-id <TemplateId> --region cn-shanghai -o template.json

# Local expansion (no cloud call or charge)
python "$SKILL_DIR/scripts/template_editor.py" expand \
  --template template.json --clips-param clips.json -o timeline_expanded.json

# Render from the template
python "$SKILL_DIR/scripts/template_editor.py" submit \
  --template-id <TemplateId> --clips-param clips.json \
  --output-config output.json --region cn-shanghai --yes
```

## Parameter Rules

- A scalar parameter starts with `$`: `"MediaId": "$Video"`.
- A default follows a colon: `"X": "$X:40"`. If the default is `NULL` and no value is supplied, ICE removes that field from the expanded Timeline.
- Keep JSON value types intentional. If a Timeline field is numeric, prefer a numeric default such as `$X:40`; incoming `ClipsParam` values shown by the API may still be strings.
- `ClipsParam` keys omit `$`: `$Video` becomes `{"Video":"<mediaId>"}`.
- For clipping source media, use `In` and `Out`. `TimelineIn` and `TimelineOut` place or bound the clip on the composition timeline; they are not substitutes for source clipping. A slot named `VideoDuration` describes only the field it replaces: when it maps to `Out`, supply the intended source endpoint, not mechanically the full media duration. For a shorter narration starting at zero, use `Out = min(source duration, narration duration)`.

## Variable-Length Arrays

Use `ArrayItems` inside an existing clips array:

```json
{
  "Sys_Type": "ArrayItems",
  "Sys_ArrayObject": "$VideoArray",
  "Sys_Template": {"MediaId": "$MediaId"}
}
```

Supply either the explicit object form:

```json
{"VideoArray":[{"MediaId":"id-1"},{"MediaId":"id-2"}]}
```

or, when `Sys_Template` has exactly one parameter, the shorthand:

```json
{"VideoArray":["id-1","id-2"]}
```

ICE flattens an `ArrayItems` result that sits between fixed opening and ending clips. Use `Sys_Type: Array` only when the surrounding field itself is the generated array, as in the `AudioTrackClips` example generated by `mute-with-audio`.

## Included Presets

| Preset | Variables | Fixed inputs |
|---|---|---|
| `video-concat` | `VideoArray` | None |
| `opening-ending` | `VideoArray` | `--opening-media-id`, `--ending-media-id` |
| `watermark` | `VideoArray` | `--watermark-image-id`; default 200×60 at (40,40) |
| `mute` | `VideoArray` | Adds `Volume` with `Gain: "0"` |
| `mute-with-audio` | `VideoArray`, `AudioArray` | Mutes video and lays complete audio clips over it |

Presets are starters, not mandates. For text slots, adaptive behavior, transitions, subtitles, or custom geometry, write Config from the Timeline references and parameterize only the values callers should replace. Do not expose every field merely because it can be exposed.

## Rendering and Safety

- `AddTemplate` creates a persistent cloud resource. Never call it without showing the Config contract and receiving confirmation.
- `SubmitMediaProducingJob` is billable and can overwrite an OSS object. Apply the same confirmation, idempotency, polling, signed-URL, and verification rules as direct Timeline jobs.
- A `TemplateId` is region-bound in practice: create, inspect, and render it through the same ICE region.
- Media replacements may be MediaIds or OSS HTTP(S) URLs and may be mixed, but each MediaId must belong to the job region.
- Fetch the template before a render when the caller did not provide the slot contract. Never guess numeric IDs such as `"1"`, because console-created templates assign those IDs through variable-material management.
- `ClipsParam` is a rendering input, not part of the stored Config. Never bake per-run user media into the template unless it is intentionally a fixed opening, ending, watermark, or other permanent asset.

## Common Custom Configs

Scalar video plus fixed watermark:

```json
{
  "VideoTracks": [{"VideoTrackClips": [{"MediaId": "$Video"}]}],
  "ImageTracks": [{"ImageTrackClips": [{
    "ImageId": "fixed-logo-id",
    "Width": 200,
    "Height": 60,
    "X": "$X:40",
    "Y": "$Y:40",
    "TimelineIn": "$TimelineIn:0",
    "TimelineOut": "$TimelineOut:NULL"
  }]}]
}
```

Video array muted with a complete audio array:

```json
{
  "VideoTracks": [{"VideoTrackClips": [{
    "Sys_Type": "ArrayItems",
    "Sys_ArrayObject": "$VideoArray",
    "Sys_Template": {
      "MediaId": "$MediaId",
      "Effects": [{"Type": "Volume", "Gain": "0"}]
    }
  }]}],
  "AudioTracks": [{"AudioTrackClips": {
    "Sys_Type": "Array",
    "Sys_ArrayObject": "$AudioArray",
    "Sys_Template": {"MediaId": "$MediaId"}
  }}]
}
```

If narration is shorter than the source video, trim the video `Out` to the narration endpoint; matching `Out-In` and `TimelineOut-TimelineIn` avoids a black/silent tail. If narration is longer than the concatenated video, the result remains bounded by the video track and excess audio is truncated: repeat the video as adjacent `ArrayItems` entries until it covers the narration, then trim the last entry. Do not use video `LoopMode`; `expand` and `submit` block mismatched video-loop spans because only audio looping is evidenced.

## Render Report

For a template render, report the final `ClipsParam`, JobId, MediaId, source/narration/output durations, per-stream durations from `media-info`, the tail-silence/loudness result, and the final-frame finding. If equal video spans made `LoopMode` a no-op, say plainly that the output trims the source to that span rather than looping it.
