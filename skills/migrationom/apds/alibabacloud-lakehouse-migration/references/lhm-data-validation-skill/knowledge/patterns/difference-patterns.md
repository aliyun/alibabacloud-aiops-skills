# 差异模式知识库

## 分类体系

- **正常差异（Expected）**：方言固有差异导致，业务可接受，无需修复
- **可处理差异（Actionable）**：可通过配置调整或自定义 SQL 解决
- **异常差异（Critical）**：数据丢失或错误，需要修复

---

## 模式 1：DECIMAL 精度误差

**分类**：正常差异

| 维度 | 说明 |
|------|------|
| **特征** | 差异率 < 0.01%，差异值集中在小数部分，指标校验中 AVG/SUM 有微小偏差 |
| **触发条件** | 数据源对涉及 Redshift（使用 CONVERT(float, col)）vs MaxCompute（使用 CAST(col AS DECIMAL)） |
| **根因** | IEEE 754 浮点精度（约 7 位有效数字）vs 精确 DECIMAL 计算 |
| **影响** | 低 — 业务通常可接受 |
| **建议** | 配置 diffTolerateValues，如 `{"amount_col": 0.001}` |

---

## 模式 2：DECIMAL 前导零缺失（已修复）

**分类**：异常差异（已修复版本可消除）

| 维度 | 说明 |
|------|------|
| **特征** | 弱内容校验中，小数 < 1 的值（如 0.1）因前导零差异导致 MD5 不一致 |
| **触发条件** | 数据源对涉及 PostgreSQL 系（PG/Redshift/GaussDB/Hologres/ADBPG） |
| **根因** | PG 的 TO_CHAR 使用 '9' 格式化时，前导零被替换为空格，TRIM 后 0.1 变成 .1 |
| **影响** | 高 — 误报为差异，实际数据一致 |
| **建议** | 升级到 v1.17.2+（PostgresDialect.getDecimalFormatter 已修复，自动补前导零） |
| **受益方言** | PostgreSQL、Redshift、GaussDB、Hologres、ADBPG |

## 模式 3：SUPER/JSON 类型 NULL 处理（已修复）

**分类**：异常差异（已修复版本可消除）

| 维度 | 说明 |
|------|------|
| **特征** | 弱内容校验中，JSON/ARRAY 类型字段差异率 100% |
| **触发条件** | 数据源涉及 Redshift SUPER 类型 |
| **根因** | Redshift SUPER 类型通过 ::text 转换时返回 NULL，COALESCE(NULL, '') 得到空字符串（数据丢失） |
| **影响** | 高 — 数据完全丢失 |
| **建议** | 升级到 v1.17.2+（RedShiftDialect 已修复，JSON 类型使用 JSON_SERIALIZE 替代 ::text） |

---

## 模式 4：CRC32 算法不兼容（不可修复）

**分类**：异常差异（算法层面不兼容）

| 维度 | 说明 |
|------|------|
| **特征** | 弱内容校验 CRC32 全部不一致 |
| **触发条件** | 数据源对涉及 Redshift 与 MaxCompute/Hive |
| **根因** | 双重不兼容：1) 返回值类型不同（hex 字符串 vs 无符号整数）2) CRC-32 多项式不同 |
| **影响** | CRC32 校验完全不可用 |
| **建议** | 使用 MD5 替代 CRC32；在方案推荐阶段即禁用 CRC32 |
| **验证** | crc32('123456789'): Redshift 返回 'e3069283'（非标准），标准值应为 'cbf43926' |

## 模式 5：ARRAY 元素顺序不一致

**分类**：可处理差异

| 维度 | 说明 |
|------|------|
| **特征** | ARRAY 字段 CRC32/MD5 不一致，但元素集合相同 |
| **触发条件** | 数据源对涉及 Redshift（无 sort_array 函数） |
| **根因** | ARRAY 元素顺序在迁移过程中可能改变，Redshift 无 sort_array 无法保证顺序一致 |
| **影响** | 中 — 取决于业务是否关心顺序 |
| **建议** | 使用自定义 SQL 校验元素集合（忽略顺序），见 custom-check-sql.md 模式 1 |

---

## 模式 6：TIMESTAMP 时区偏移

**分类**：可处理差异

| 维度 | 说明 |
|------|------|
| **特征** | TIMESTAMP 字段差异值固定为 8 小时（28800 秒）或 N 小时 |
| **触发条件** | 源端使用 UTC，目标端使用本地时区（或反之） |
| **根因** | ETL 过程中未显式处理时区转换 |
| **影响** | 中 — 需确认业务时区要求 |
| **建议** | 1) 在 ETL 中显式转换时区 2) 使用自定义 SQL 校验（DATE_FORMAT 统一格式后比对） 3) 如业务可接受，排除 TIMESTAMP 字段 |

---

## 模式 7：NULL vs 空字符串

**分类**：可处理差异

| 维度 | 说明 |
|------|------|
| **特征** | 差异行中源端为 NULL，目标端为空字符串（或反之） |
| **触发条件** | 数据源对的 NULL 语义不同 |
| **根因** | 迁移工具将 NULL 转换为空字符串（或反之） |
| **影响** | 中 — 取决于业务对 NULL 和空字符串的区分 |
| **建议** | 1) 配置 NULL 映射规则 2) 使用自定义 SQL 校验（COALESCE 统一处理） |

---

## 模式 8：BOOLEAN 格式化差异

**分类**：正常差异

| 维度 | 说明 |
|------|------|
| **特征** | BOOLEAN 字段弱内容校验不一致 |
| **触发条件** | 数据源对涉及不同 BOOLEAN 表示方式（true/false vs 1/0 vs t/f） |
| **根因** | 不同方言的 BOOLEAN 序列化格式不同 |
| **影响** | 低 — 数据语义相同，格式不同 |
| **建议** | 使用指标校验（COUNT）替代弱内容校验，或在模板中排除 BOOLEAN 字段 |

## 模式 9：大字段（TEXT/BLOB）截断

**分类**：异常差异

| 维度 | 说明 |
|------|------|
| **特征** | TEXT/LONGTEXT 类型字段差异率较高，差异值集中在长文本 |
| **触发条件** | 迁移工具对大字段有截断限制 |
| **根因** | ETL 工具或目标端对字段长度有限制 |
| **影响** | 高 — 数据丢失 |
| **建议** | 1) 检查 ETL 配置 2) 检查目标端字段长度 3) 排除超长字段 |

---

## 模式 10：行数不一致

**分类**：异常差异

| 维度 | 说明 |
|------|------|
| **特征** | 数据量校验中，源端行数 != 目标端行数 |
| **触发条件** | 数据迁移不完整 |
| **根因** | ETL 过程中数据丢失或重复（过滤条件、去重逻辑、并发写入等） |
| **影响** | 高 — 数据完整性问题 |
| **建议** | 1) 检查 ETL 日志 2) 检查过滤条件 3) 检查去重逻辑 4) 重跑 ETL |

## 模式 11：Hive 隐式类型转换差异

**分类**：可处理差异

| 维度 | 说明 |
|------|------|
| **特征** | 部分字段不一致，集中在 STRING→NUMBER 隐式转换的场景 |
| **触发条件** | 数据源对涉及 Hive，且 ETL 过程中有隐式类型转换 |
| **根因** | Hive 的隐式类型转换规则较宽松（STRING→NUMBER 转换失败返回 NULL 而非报错），其他方言可能直接报错或返回不同值 |
| **影响** | 中 — 数据语义可能不同 |
| **建议** | 1) 在 ETL 中显式 CAST 类型 2) 使用指标校验时排除类型不匹配的字段 3) 使用自定义 SQL 校验显式转换后的值 |

## 模式 12：分区命名格式差异

**分类**：可处理差异

| 维度 | 说明 |
|------|------|
| **特征** | 分区校验失败，或分区无法匹配 |
| **触发条件** | 源端和目标端的分区命名规范不同 |
| **根因** | 分区值格式不一致：如 `dt=2024-01-01` vs `dt=20240101`，或 `pt=20240101` vs `ds=20240101`（分区键名不同） |
| **影响** | 高 — 分区无法对应，校验结果不可比 |
| **建议** | 1) 确认分区键名映射（source_partition vs target_partition） 2) 确认分区值格式映射 3) 在任务配置中显式指定分区映射 |

---

## 模式 13：ORC/Parquet 编码极少数行差异

**分类**：正常差异

| 维度 | 说明 |
|------|------|
| **特征** | 弱内容校验中，极少数行（< 0.01%）MD5/CRC32 不一致，差异行无规律 |
| **触发条件** | 源端和目标端使用不同的底层存储格式（如 Hive ORC vs MaxCompute 内部格式） |
| **根因** | ORC/Parquet 等列式存储的编码方式在不同引擎中实现有微小差异（如 decimal 编码精度、null bitmap 等） |
| **影响** | 低 — 业务数据实际一致，仅编码层面差异 |
| **建议** | 1) 配置 threshold 容忍极低差异率（如 99.99%） 2) 使用指标校验替代弱内容校验 3) 如差异率 > 0.1% 则需排查是否为真实数据问题 |

---

## 模式 14：字符集/编码差异

**分类**：异常差异

| 维度 | 说明 |
|------|------|
| **特征** | STRING 类型字段差异率较高，差异值集中在中文/特殊字符，呈现乱码特征 |
| **触发条件** | 源端和目标端字符集不同（如 GBK vs UTF-8） |
| **根因** | ETL 过程中未正确处理字符集转换，导致中文或特殊字符乱码 |
| **影响** | 高 — 数据丢失或损坏 |
| **建议** | 1) 检查 ETL 字符集配置 2) 检查源端和目标端字符集 3) 在 ETL 中显式指定字符集转换 |
