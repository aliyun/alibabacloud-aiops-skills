# Alibaba Cloud ECS Disk Performance / IO Bottleneck Diagnostic Guide

## Overview

This guide provides the specialized diagnostic design for the **Disk Performance /
IO Bottleneck** scenario of the ECS Instance Diagnostics Skill. It leverages the EBS
(Elastic Block Storage) diagnosis service (CloudLens for EBS) to automatically detect
IO latency, IOPS/throughput limits, instance-disk spec mismatches, IO hang, slow IO,
and cost-optimization opportunities on cloud disks, and outputs actionable
recommendations into the unified ECS diagnostic report.

**EBS API basics** (invoked through the `aliyun` CLI, `aliyun-cli-ebs` plugin):

| Item | Value |
|------|-------|
| popCode | `ebs` |
| API Version | `2021-07-30` |
| Endpoint | `ebs.{region}.aliyuncs.com` |
| APIs used | `DescribeLensMonitorDisks` / `CreateDiagnoseReport` / `DescribeDiagnoseReport` |
| CLI commands | `aliyun ebs describe-lens-monitor-disks` / `aliyun ebs create-diagnose-report` / `aliyun ebs describe-diagnose-report` |

> **[MUST] Use the `aliyun` CLI as the primary path.** All three EBS diagnosis APIs are
> exposed by the `aliyun-cli-ebs` plugin, which `SKILL.md`'s pre-checks install
> automatically (`aliyun configure set --auto-plugin-install true` + `aliyun plugin update`).
> The CLI reuses the already-validated CLI credentials and the unified `--user-agent`,
> so it must be preferred over the Python SDK. The Python SDK path
> (§ *Python SDK Fallback*) is only for environments where the plugin cannot be installed.

## Prerequisites & Graceful Degradation

**Pre-check command:**

```bash
# EBS plugin available? (installed by SKILL.md pre-checks)
aliyun ebs create-diagnose-report --help
```

If the command prints its parameter list, the CLI path is ready — proceed to Step 1.

> **[MUST] Degradation order** — never abandon the scenario at the first obstacle:
> 1. **CLI (primary).** If the plugin is missing, run
>    `aliyun configure set --auto-plugin-install true` and `aliyun plugin update`, then retry.
> 2. **Python SDK (fallback).** Only if the plugin still cannot be installed:
>    `pip install -r scripts/requirements.txt`, then use `scripts/diagnose_ebs_disk.py`
>    (see § *Python SDK Fallback*).
> 3. **CMS disk-metric check (last resort).** Only if both of the above are unavailable:
>    query `diskusage_utilization`, run Cloud Assistant `df -h` and
>    `du -sh /var/* /tmp/* /home/*`, retrieve and decode the output, then continue
>    the report with the available evidence.
>
> When the EBS CLI plugin is available, Steps 1–3 below MUST be attempted through the
> CLI before considering CMS fallback. When the plugin cannot be installed, proceed
> directly through the SDK and then CMS fallback order above. Reporting "diagnosis not
> executed" without attempting the highest available diagnosis path is not acceptable.

Credentials follow the same security rules as `SKILL.md` (never read/echo AK/SK;
only `aliyun configure list` to check status). The CLI path uses the CLI profile
directly. The Python SDK fallback auto-discovers credentials from:
1. Environment variables: `ALIBABA_CLOUD_ACCESS_KEY_***` / `ALIBABA_CLOUD_ACCESS_KEY_***`
2. Credentials file: `~/.alibabacloud/credentials`
3. ECS RAM role (when running on Alibaba Cloud ECS)

> **Note:** the SDK does **not** read the `aliyun` CLI profile (`~/.aliyun/config.json`).
> In sessions where credentials only exist in the CLI profile, the SDK path will fail to
> authenticate — another reason the CLI is the primary path.

**[MUST] User-Agent** — every CLI command carries the unified flag (same `{session-id}`
as generated in `SKILL.md`):

```
--user-agent "AlibabaCloud-Agent-Skills/alibabacloud-ecs-diagnose/{session-id} skill-version/{skill-version}"
```

For the Python SDK fallback, inject the same value via `Config(user_agent=...)`.

**[MUST] Session-ID reuse** — when invoking `scripts/diagnose_ebs_disk.py`, the
session-id already generated by the main skill MUST be passed in (via `--session-id`
or the `SKILL_SESSION_ID` environment variable); the script MUST NOT be left to
generate a new ID on its own.

## Parameter Confirmation

> **IMPORTANT: Parameter Confirmation** — Before executing any command or API call,
> ALL user-customizable parameters (e.g., RegionId, DiskId, time ranges, etc.)
> MUST be confirmed with the user. Do NOT assume or use default

| Parameter Name | Required/Optional | Description | Default Value |
|----------------|-------------------|-------------|---------------|
| `RegionId` | Required | The region where the disk is located | User must specify |
| `DiskId` | Required | The ID of the disk to diagnose | User must specify or select from list |

| `EndTime` | Optional | Diagnosis end time (ISO 8601 format) | Current time |

**Time range constraints:**
- If `StartTime` and `EndTime` are omitted, diagnosis covers the last 12 hours
- Maximum diagnosis period: 3 days
- `StartTime` can be up to 30 days in the past
- Time format: ISO 8601 UTC (e.g., `2026-08-20T00:00:00Z`)

## Step 1: Identify Target Disk

If the user directly provides a valid `DiskId` (format `d-xxx`), skip the listing and
go to Step 2 after confirming it together with `RegionId`.

Otherwise, list the disks in the region. **If Phase 0 of `SKILL.md` has already located
an `InstanceId`**, filter by that instance so only its disks are shown.

```bash
# CloudLens-monitored disks (preferred — same data source as the diagnosis service)
aliyun ebs describe-lens-monitor-disks \
  --biz-region-id <region> \
  --max-results 100 \
  --user-agent "AlibabaCloud-Agent-Skills/alibabacloud-ecs-diagnose/{session-id} skill-version/{skill-version}"

# Fallback listing (also used to verify a user-supplied DiskId exists)
aliyun ecs describe-disks \
  --biz-region-id <region> \
  --disk-ids '["d-xxx"]' \
  --user-agent "AlibabaCloud-Agent-Skills/alibabacloud-ecs-diagnose/{session-id} skill-version/{skill-version}"
```

`describe-lens-monitor-disks` returns the disks in the `Data` array. If it returns an
empty `Data` (CloudLens for EBS not enabled in the account), do **not** stop: use
`aliyun ecs describe-disks` to enumerate/verify disks and still attempt Step 2 —
`CreateDiagnoseReport` is the authoritative check for diagnosability.

**Display format:** present the candidate disks in a Markdown table and ask the user
to select one:

| DiskId | Size (GB) | Type | Category | Status | Instance |
|--------|-----------|------|----------|--------|----------|
| d-xxx1 | 100 | cloud_essd | PL1 | In_use | i-xxx1 |
| d-xxx2 | 500 | cloud_ssd | - | In_use | i-xxx1 |

The bundled Python fallback script supports listing too:

```bash
python3 scripts/diagnose_ebs_disk.py --region <region> --list-disks \
  --instance-id <instance-id> --session-id <session-id>
```

## Step 2: Initiate Diagnosis

After confirming `DiskId` and `RegionId` (and the optional time range) with the user,
call `CreateDiagnoseReport`:

```bash
aliyun ebs create-diagnose-report \
  --biz-region-id <region> \
  --diagnose-type Performance \
  --resource-type Disk \
  --resource-id <disk-id> \
  --user-agent "AlibabaCloud-Agent-Skills/alibabacloud-ecs-diagnose/{session-id} skill-version/{skill-version}"
```

| Parameter | CLI flag | Value |
|-----------|----------|-------|
| `RegionId` | `--biz-region-id` | Confirmed region |
| `DiagnoseType` | `--diagnose-type` | `Performance` |
| `ResourceType` | `--resource-type` | `Disk` (note the capital 'D') |
| `ResourceId` | `--resource-id` | Confirmed DiskId |
| `StartTime` / `EndTime` | `--start-time` / `--end-time` | Optional, confirmed time range |

A successful call returns a `ReportId` used for polling in Step 3.

## Step 3: Poll Diagnosis Status

Poll `DescribeDiagnoseReport` **every 1 second**, with a client-side timeout of
**5 minutes** (300 seconds):

```bash
REPORT_ID=<report-id>
for i in $(seq 1 300); do
  STATUS=$(aliyun ebs describe-diagnose-report \
    --biz-region-id <region> \
    --diagnose-type Performance \
    --report-ids "$REPORT_ID" \
    --user-agent "AlibabaCloud-Agent-Skills/alibabacloud-ecs-diagnose/{session-id} skill-version/{skill-version}" \
    | tee /tmp/ebs_report.json | jq -r '.Reports[0].Status')
  echo "[Poll #$i] Status: $STATUS"
  [ "$STATUS" != "Running" ] && break
  sleep 1
done
cat /tmp/ebs_report.json
```

> `--report-ids` is a **list** flag: space-separated values, not a JSON array.

**Status values:**

| Status | Meaning | Action |
|--------|---------|--------|
| `Running` | Diagnosis in progress | Continue polling |
| `Success` | Diagnosis completed | Proceed to Step 4 |
| `Fail` | Diagnosis failed | Inform user and terminate this scenario |
| `TimeOut` | Service-side timeout | Inform user; suggest a shorter time range and retry |

## Step 4: Analyze Diagnosis Results

Once status is `Success`, parse the report's `Severity` and `Events` fields.

**Severity levels:**

| Severity | Meaning | User Action |
|----------|---------|-------------|
| **Normal** | No issues detected | Inform user disk performance is healthy |
| **Info** | Related information, may be associated with anomalies | Highlight for user attention (cost, alignment, etc.) |
| **Warn** | Warning, may cause performance issues | Provide optimization recommendations |
| **Critical** | Critical issue affecting performance | Strongly recommend immediate action |

**Common diagnosis events (quick reference):**

| EventName | Severity | Recommendation |
|-----------|----------|----------------|
| InstanceIOPSExceedInstanceMaxLimit / InstanceBPSExceedInstanceMaxLimit | Warn | Monitor business impact; upgrade instance if needed |
| DiskIOPSExceedInstanceMaxLimit / DiskBPSExceedInstanceMaxLimit | Warn | Monitor business impact |
| DiskIOPSExceedDiskMaxLimit / DiskBPSExceedDiskMaxLimit | Warn | Reduce IO frequency or upgrade disk type / expand capacity |
| DiskSpecNotMatchedWithInstance | Warn | Upgrade instance spec based on business needs |
| DiskIOHang | Warn/Critical | Check performance metrics and OS-level IO issues |
| SlowIO | Warn | Monitor business impact and investigate IO bottlenecks |
| CostOptimization / DiskIONo4kAligned / BurstIO / BurstIOFeeSealing | Info | Cost / alignment / burst-fee review |
| NoSnapshot | Warn | Create snapshots to protect data |

Use the event name, severity, description, first occurrence, and recommended action returned by the diagnosis report to provide event-specific remediation.

## Step 5: Provide Recommendations (Report Integration)

Fill the diagnosis results into a standalone **【Disk Performance Diagnostics】** section.
The heading is a required literal and MUST remain exactly in English, even when the
rest of the report is localized:

```
【Disk Performance Diagnostics】
  Disk ID:  d-bp1xxxxxxxxxxxxx
  Severity: Warn
  Events:
    | EventName | Severity | Description | First Occurrence |
    |-----------|----------|-------------|------------------|
    | SlowIO    | Warn     | ...         | 2026-08-20T...   |
  Recommendations:
    1. SlowIO: investigate IO bottlenecks (iostat -x 1, iotop) ...
```

Recommendation guidance by event category:
1. **IOPS/BPS limit issues**: consider upgrading instance or disk specifications
2. **Spec mismatch**: recommend matching instance and disk specs
3. **Cost optimization**: suggest adjusting ESSD AutoPL performance levels
4. **IO hang / slow IO**: check application-level IO patterns and OS configuration
   (can be combined with Deep Diagnostics via Cloud Assistant, e.g. `iostat`, `iotop`)
5. **Snapshot warnings**: suggest creating automatic snapshot policies

Also merge `Warn`/`Critical` findings into the report's 【Issue Summary】 and
【Recommendations】 sections.

## Python SDK Fallback

> Use this **only** when the `aliyun-cli-ebs` plugin cannot be installed. Prefer the
> bundled script `scripts/diagnose_ebs_disk.py` over ad-hoc code.

**[MUST] SDK pitfalls** (each of these has caused a real failure — do not "fix" the
template back to the broken forms):

| Pitfall | Wrong | Correct |
|---------|-------|---------|
| `RuntimeOptions` location | `open_api_models.RuntimeOptions(...)` → `AttributeError` | `from alibabacloud_tea_util import models as util_models` → `util_models.RuntimeOptions()` |
| User-Agent injection | `RuntimeOptions(headers={'User-Agent': ...})` → `TypeError: unexpected keyword argument 'headers'` | `open_api_models.Config(..., user_agent=UA)` |
| Query value types | `{'MaxResults': 100}` (int) → `TypeError: quote() doesn't support 'encoding' for bytes` | every value a **string**: `{'MaxResults': '100'}` |
| List parameters | `{'ReportIds': [report_id]}` (Python list) | flattened index form: `{'ReportIds.1': report_id}` |

```bash
python3 -c "import alibabacloud_tea_openapi"   # verify SDK
pip install -r scripts/requirements.txt         # install if missing
```

```python
import json
import time
from alibabacloud_tea_openapi.client import Client as OpenApiClient
from alibabacloud_tea_openapi import models as open_api_models
from alibabacloud_tea_util import models as util_models
from alibabacloud_credentials.client import Client as CredentialClient
from Tea.exceptions import TeaException

region_id = 'cn-hangzhou'        # MUST confirm with user
disk_id = 'd-bp1xxxxxxxxxxxxx'   # MUST confirm with user
session_id = '<session-id>'      # 32-char lowercase hex generated for this session
skill_version = '<skill-version>'  # read from the package manifest
user_agent = f'AlibabaCloud-Agent-Skills/alibabacloud-ecs-diagnose/{session_id} skill-version/{skill_version}'

credential = CredentialClient()
config = open_api_models.Config(
    credential=credential,
    endpoint=f'ebs.{region_id}.aliyuncs.com',
    user_agent=user_agent          # unified User-Agent (MUST)
)
client = OpenApiClient(config)
runtime_options = util_models.RuntimeOptions()

def call(action, queries):
    params = open_api_models.Params(
        action=action, version='2021-07-30', protocol='HTTPS',
        method='POST', auth_type='AK', style='RPC'
    )
    # every query value MUST be a string
    request = open_api_models.OpenApiRequest(
        query={k: str(v) for k, v in queries.items()}
    )
    response = client.call_api(params, request, runtime_options)
    return json.loads(response['body'].decode('utf-8'))

# Step 2: initiate diagnosis
result = call('CreateDiagnoseReport', {
    'RegionId': region_id,
    'DiagnoseType': 'Performance',
    'ResourceType': 'Disk',      # Note: capital 'D'
    'ResourceId': disk_id
    # Optional: 'StartTime': '2026-08-20T00:00:00Z', 'EndTime': '2026-08-21T00:00:00Z'
})
report_id = result.get('ReportId')

# Step 3: poll every 1 second, 5-minute timeout
deadline = time.time() + 300
while time.time() < deadline:
    result = call('DescribeDiagnoseReport', {
        'RegionId': region_id,
        'DiagnoseType': 'Performance',
        'ReportIds.1': report_id     # list params use the flattened index form
    })
    reports = result.get('Reports') or []
    status = reports[0].get('Status') if reports else None
    if status == 'Success':
        print(json.dumps(reports[0], indent=2))
        break
    if status in ('Fail', 'TimeOut'):
        print(f'Diagnosis failed with status: {status}')
        break
    time.sleep(1)
```

Equivalent script usage:

```bash

  --region <region> --disk-id <disk-id> --session-id <session-id> --yes
```

> confirmed with the user; without `--yes` the script blocks waiting on stdin.

## Error Handling

For CLI calls, inspect the printed `Code` / `Message` / `RequestId`. For the Python
fallback, catch `TeaException` and inspect `e.code` / `e.message`:

```python
try:
    result = call(action, queries)
except TeaException as e:
    print(f'API Error: {e.code} - {e.message}')
```

**Common errors:**

| Error Code | Cause | Handling |
|------------|-------|----------|
| `unknown flag: --region-id` (CLI) | Wrong region flag | Use `--biz-region-id`; confirm via `aliyun ebs <command> --help` |
| `InvalidParameter` / `MissingParameter` | Wrong `ResourceType` casing (must be `Disk`), missing `--diagnose-type`, invalid ISO 8601 time, range > 3 days, or StartTime > 30 days old | Fix parameters and retry |
| `NoSuchResource` (404) / `InvalidDiskId.NotFound` | DiskId does not exist in this region/account | Verify with `aliyun ecs describe-disks --biz-region-id <region> --disk-ids '["d-xxx"]'`. If `TotalCount = 0`, STOP and report that the disk does not exist — **do NOT substitute another disk** (same rationale as the Phase 0 empty-result protocol in `SKILL.md`) |
| CloudLens not enabled (empty `Data` from `describe-lens-monitor-disks`, or diagnosis rejected) | Block Storage Data Insights (CloudLens for EBS) is off for the account | Report it and point the user to ECS Console → Block Storage Data Insights to enable it (`aliyun ebs apply-lens-service` is state-changing — **recommend only, never execute**), then fall back to the CMS disk-metric check |
| `Forbidden.RAM` / `Forbidden.Unauthorized` | Missing `ebs:*` RAM permissions | Follow the permission failure process below |
| `ServiceUnavailable` / `InternalError` / `Throttling.User` | Transient service/throttling error | Retry with exponential backoff (1s/2s/4s) |
| Report `Status: Fail` ("Insufficient monitoring data") | No monitoring data in the chosen range | Retry with default range (last 12 hours) |

> **[MUST] Permission Failure Handling:** When any EBS API call fails due to
> permission errors (`Forbidden.RAM`, `Forbidden.Unauthorized`), follow the existing
> process defined in `SKILL.md`:
> 1. Identify the missing EBS permission from the required permissions listed below
> 2. Use `ram-permission-diagnose` skill to guide the user through requesting it
> 3. Pause and wait until the user confirms that the permission has been granted

Required EBS permissions (all L1 / low risk, read-only diagnosis):
`ebs:DescribeLensMonitorDisks`, `ebs:CreateDiagnoseReport`, `ebs:DescribeDiagnoseReport`.
