# System Crash Diagnostics

## Overview

Diagnoses Windows BugCheck BSOD events, Crash Dump configuration and dump file collection. Covers: crash event query (Step 1), crash configuration diagnostics (Step 2), generated dump retrieval and crash platform analysis (Step 3).

> The online side can only query and collect information on historical crash / hang events; it does not have real-time analysis capability. In-depth analysis requires collecting dump files for analysis. NMI core collection when the instance is still in a hung state is an offline scenario (see references/offline/crash-hang.md), performed manually by the user.

**Input**: User problem description (required)
**Output**: Root cause list (root_cause / severity / evidence / explanation / fix)

## Step Selection Guide

**Not all steps need to be executed.** Select relevant steps based on the user's described problem symptoms:

| User Symptom | Recommended Steps |
|-------------|---------------|
| BSOD, BugCheck | Step 1 (BugCheck BSOD events) -> Step 2 (Crash Dump configuration) -> Step 3 (dump retrieval and in-depth analysis) |
| Crash and restart | Step 1 -> Step 2 -> Step 3 |
| Need in-depth analysis after a crash | Step 1 -> Step 3 |
| Hang / Frozen (already force-restarted and recovered, or still hung) | Step 1 -> Step 2: Onsite can only perform historical event query and configuration check; if already recovered, onsite evidence is lost; if still hung, guide the user to manually trigger NMI core collection per offline diagnostics (crash-hang.md) |

## Diagnostic Steps

### Step 1: BugCheck BSOD Event Check

**Data Collection**:

> Collection target: Query BugCheck BSOD records in the system event log (EventID 1001, Source "BugCheck")
>
> Time window constraint: The script collects the last 30 days by default; after the user provides the BSOD time point, you MUST narrow StartTime/EndTime centered on that time point (e.g., 1 day before to 1 day after) and re-collect, to avoid falsely concluding "no BSOD" when there are no records in the default window.

- PowerShell script: [system-crash.ps1](references/online/scripts/system-crash.ps1) Section Step 1

**Analysis Approach**:

1. Check BugCheck BSOD events:
   - Normal: No BugCheck records within the collection window -> No BSOD events in the window (confirm the window covers the user's reported fault time point)
   - Abnormal: EventID 1001 BugCheck records exist -> **Root cause**: A BSOD crash occurred recently (CriticalEvent), **Severity**: Critical

> The Message field of BugCheck events contains the BugCheck Code (e.g., 0x0000009F, 0x000000D1), which can be used to identify the crash cause.

### Step 2: Crash Dump Configuration Check

**Data Collection**:

> Collection target: Retrieve CrashControl registry configuration to confirm whether Crash Dump is enabled

- PowerShell script: [system-crash.ps1](references/online/scripts/system-crash.ps1) Section Step 2

**Analysis Approach**:

1. Check CrashDumpEnabled configuration:
   - 0: Disabled -> **Root cause**: Crash Dump is not enabled; no dump file can be generated after a BSOD (CrashDumpNotEnabled), **Severity**: Warning
   - 1 (Complete), 2 (Kernel), 3 (Small 64KB), or 7 (Automatic, recommended): **Normal**

### Step 3: Generated Crash Dump Retrieval and In-depth Analysis (Crash Scenario)

**Applicable conditions**: The system has experienced a BSOD and has currently recovered; dump files need to be retrieved for in-depth crash cause analysis.

**Data Collection**:

> Collection target: Check dump files generated by previous BSODs (%SystemRoot%\MEMORY.DMP and the Minidump directory)

```powershell
Get-ChildItem -Path "$env:SystemRoot\MEMORY.DMP" -ErrorAction SilentlyContinue
Get-ChildItem -Path "$env:SystemRoot\Minidump\*.dmp" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name, LastWriteTime, Length
```

**Analysis Approach**:

1. Dump file exists and modification time matches the BSOD time point -> Analyze the dump file content to identify the BSOD root cause; if analysis capability is insufficient, inform the user honestly and provide the dump file path information for expert analysis
2. No dump file -> Route to the `GuestOS.DumpProductionFailed` domain (see [WORKFLOW-GUIDE.md](references/online/WORKFLOW-GUIDE.md)) to investigate why no dump was generated (Crash Dump configuration / page file / disk space)
