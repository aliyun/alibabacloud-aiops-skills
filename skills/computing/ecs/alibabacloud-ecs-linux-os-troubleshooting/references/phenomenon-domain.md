# Linux phenomenon domain index

When narrowing a customer's natural-language description to a domain, first read [`symptom-to-domain.md`](symptom-to-domain.md). The table below is the authoritative enumeration and link index.

## Startup issues


| Phenomenon domain category | Phenomenon domain | Unique identifier | Concept explanation | Typical symptoms | Troubleshooting process | Recommended diagnostic set |
| ----- | ------------------------------ | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------- |
| Startup issues | The instance stays in the "Starting" state | GuestOS.UnexpectedlySlowStarting | The instance state describes the whole lifecycle from creation to release. "Starting" is an intermediate state that indicates the platform is preparing hardware resources and control-plane data, and it normally becomes "Running" within one minute. Staying in this state for too long means the startup phase is abnormal. See: [Instance lifecycle](https://help.aliyun.com/zh/ecs/user-guide/instance-lifecycle) | The instance starts slowly, fails to start, or behaves abnormally; the console shows the instance as "Starting" and it does not become "Running" for a long time | [instance-stuck-starting.md](instance-stuck-starting.md) | — |
| Startup issues | The instance is already in the "Running" state, but GuestOS has not started normally | GuestOS.SystemBootstrapFailed | "Running" means that the control plane and virtualization are ready and the instance is powered on. It **does not mean that the operating system or workloads are running**. Underlying issues, configuration issues, file exceptions, and other problems can prevent GuestOS from starting normally. See: [Instance lifecycle](https://help.aliyun.com/zh/ecs/user-guide/instance-lifecycle), [Health diagnosis and solutions for instances that cannot start](https://help.aliyun.com/zh/ecs/support/repair-instance-of-the-operating-system-can-t-start-the-operational-guidelines-for-school-official-cites-use-of-the-problem) | The customer reports that remote connection/logon fails or the service is unavailable; VNC does not reach the normal logon screen, is stuck at systemd, or reports errors; no bootable device, kernel stuck, UEFI/grub shell, missing files, emergency mode, etc. | [guestos-not-running.md](guestos-not-running.md) | dms-osstartfailconsole |


## Usage issues


| Phenomenon domain category | Phenomenon domain | Unique identifier | Concept explanation | Typical symptoms | Troubleshooting process | Recommended diagnostic set |
| ----- | ---------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------- |
| Usage issues | Disk partition table, partitions, or file system is damaged or does not meet expectations | GuestOS.CorruptDiskStorage | Disks usually require a partition table/partitions and a file system before they can be accessed. Common partition tables include MBR/GPT; common file systems include ext4/xfs. Damage or mount behavior that does not meet expectations can cause startup exceptions, service exceptions, or business exceptions. See [Partition table types](https://access.redhat.com/documentation/zh-cn/red_hat_enterprise_linux/9/html/managing_storage_devices/comparison-of-partition-table-types_disk-partitions), [File system overview](https://access.redhat.com/documentation/zh-cn/red_hat_enterprise_linux/9/html/managing_file_systems/overview-of-available-file-systems_managing-file-systems), [Initialize a data disk](https://help.aliyun.com/zh/ecs/user-guide/overview-27) | Data cannot be accessed, the file system is damaged, the disk cannot be mounted or is not mounted correctly, data is lost, file system information is lost, etc. See [Block Storage FAQ](https://help.aliyun.com/zh/ecs/user-guide/faq-4) | [disk-fs-damaged.md](disk-fs-damaged.md) | dms-instancedefault |
| Usage issues | Abnormal clock drift or jump | GuestOS.AbnormalClockDrift | An instance has a system clock and a hardware clock (RTC, emulated by virtualization). The initial RTC value is determined by the image standardizedTimeZone (true→UTC, false→Beijing time). The system has a time zone and RTC on localtime; they must be consistent with standardizedTimeZone, otherwise time is prone to disorder. There are also NTP/chrony, fixed time-zone settings, and other factors. See [NTP](https://help.aliyun.com/zh/ecs/user-guide/alibaba-cloud-ntp-server), [Linux time and time zones](https://help.aliyun.com/zh/ecs/user-guide/linux-time-and-time-zones) | Time synchronization exceptions, time jumps after restart, etc. | [clock-abnormal.md](clock-abnormal.md) | dms-instancedefault |
| Usage issues | Instance cannot access the network | GuestOS.OutsideNetworkAccessFailed | For an instance to access the network, at minimum it needs: NIC IP, routes, and DNS. Primary/secondary NICs and secondary IPs all require configuration. Alibaba Cloud DNS 100.100.2.136/138 is commonly used in VPCs. See [Obtain an IP address for a secondary ENI](https://help.aliyun.com/zh/ecs/user-guide/configure-a-secondary-eni), [Assign secondary private IP addresses](https://help.aliyun.com/zh/ecs/user-guide/assign-secondary-private-ip-addresses) | cloud-init cannot connect to metadata, network remains unavailable after DHCP configuration, etc. | [internal-network-failed.md](internal-network-failed.md) | dms-instancedefault |
| Usage issues | Unable to log on to the instance through VNC | GuestOS.VNCLoginFailed | VNC is a graphical logon method provided by ECS control, and it does not depend on the instance network. Therefore, when GuestOS has not started, VNC can still be used for fault recovery. However, the VNC path is not 100% stable, and hardware/software/architecture incompatibility can cause connection failures. If OS logon is required to perform O&M, OS startup, PAM, Shell, and other exceptions can also cause logon failure. See [Connect to an instance by using VNC](https://help.aliyun.com/zh/ecs/user-guide/log-on-to-an-instance-by-using-vnc) | Black screen after VNC connection, etc. See [VNC/Workbench connection issues](https://help.aliyun.com/zh/ecs/support/through-vnc-or-workbench-instance-remote-connection-problems#705d692095lw1) | [vnc-login-failed.md](vnc-login-failed.md) | dms-instancedefault |
| Usage issues | Unable to remotely log on to the instance through SSH | GuestOS.SSHConnectingFailed | SSH provides encrypted remote connections and command execution. Connection establishment can fail because the OS has not started, the network is unreachable, firewall rules, sshd configuration, PAM, Shell, file exceptions, and other issues. See [SSH service introduction](https://help.aliyun.com/zh/ecs/ssh-service-introduction) | SSH remote logon to the instance fails or reports connection errors. See [SSH remote connection issues](https://help.aliyun.com/zh/ecs/support/ssh-remote-connection-problems) | [ssh-login-failed.md](ssh-login-failed.md) | dms-instancedefault, dms-remoteconnectdiagnose |


## Crash or hang issues


| Phenomenon domain category | Phenomenon domain | Unique identifier | Concept explanation | Typical symptoms | Troubleshooting process | Recommended diagnostic set |
| -------- | ---- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------- | ------- |
| Crash or hang issues | System hang | GuestOS.Hang | A hang means a process or the system stops responding to input (keyboard/mouse). Causes vary, including software or hardware defects, infinite loops, resource exhaustion (such as busy disks), hardware throttling, slow networks, configuration issues, or compatibility issues. The root cause is often resource exhaustion. It may recover temporarily by itself or require manual intervention. Unlike a crash, a crash occurs instantaneously. | For example, the screen shows "watchdog: BUG: soft lockup - CPU#6 stuck for 23s!". | [system-hang.md](system-hang.md) | dms-instancedefault |
| Crash or hang issues | System crash | GuestOS.Crash | A crash is a safety measure taken when the kernel detects a severe error, and it requires either manual restart or configured automatic restart. When kdump is enabled, memory dumps can be generated automatically for easier analysis. See [Collect crash dumps](https://help.aliyun.com/zh/ecs/user-guide/collect-kdump-information-after-an-instance-experiences-an-operating-system-failure), [Troubleshoot crashes](https://help.aliyun.com/zh/ecs/support/troubleshoot-instance-panic-issues), [Enable Kdump](https://help.aliyun.com/zh/ecs/how-to-enable-the-kdump-service-for-linux-instances) | The instance shuts down and restarts automatically, etc. | [system-crash.md](system-crash.md) | dms-unexpectedreboot |


## Performance issues

| ----- | -------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------ | -------------------------------------------------------- | ------- |
| Performance issues | High network retransmission rate | GuestOS.NetworkRetransmissionTooMuch | Retransmission means packets are sent again by the protocol after being dropped. A high retransmission rate is often caused by frequent retransmissions on one or more connections, mostly due to network congestion or business-process bugs. | The client detects a large number of packet retransmissions. | [retransmit-high.md](retransmit-high.md) | dms-instancedefault |
| Performance issues | High network packet send/receive latency | GuestOS.NetworkPacketIOLatencyTooHigh | The packet transmission time from source to destination, or the response time, is greater than normally expected. This is often caused by poor link quality or interactions such as TCP congestion/flow control. | Service quality degrades or timeouts occur; the network feels very slow. | [network-latency-high.md](network-latency-high.md) | dms-instancedefault |
| Performance issues | Network send/receive performance does not meet expectations | GuestOS.UnexpectedlyNetworkIOPerformance | Network send/receive performance does not meet the [instance performance SLA](https://help.aliyun.com/zh/ecs/user-guide/overview-of-instance-families). | Network BPS is too low or download speed is too slow. | [network-perf-unexpected.md](network-perf-unexpected.md) | dms-instancedefault |
| Performance issues | Abnormally high disk IOPS | GuestOS.DiskIOPSTooHigh | IOPS is the number of read/write requests per second. Abnormally high IOPS can cause storage bottlenecks and slow down the system or applications. It may be caused by high-concurrency reads/writes, defragmentation, kernel activities, and other factors. | Storage performance of business processes degrades, etc. | [disk-iops-high.md](disk-iops-high.md) | dms-instancedefault |
| Performance issues | Abnormally high load1m/load5m/load15m | GuestOS.CPULoadTooHigh | load is the average number of active processes (running + uninterruptible), reflecting overall system load. load1/5/15 are averages over the past 1/5/15 minutes. A value equal to the number of logical CPUs means the system is exactly fully loaded; a higher value means heavier load. | Processes run sluggishly, etc. | [load-high.md](load-high.md) | dms-instancedefault |
| Performance issues | High memory utilization | GuestOS.OutOfMemory | When memory utilization approaches the upper limit, the OS reclaims memory. If memory still cannot be allocated after reclamation, the OOM algorithm kills high-usage processes. | Processes suddenly exit; dmesg contains oomkill records. | [memory-oom.md](memory-oom.md) | dms-instancedefault |
| Performance issues | Disk read/write performance does not meet expectations | GuestOS.UnexpectedlyDiskIOPerformance | Disk read/write performance does not meet the [instance performance SLA](https://help.aliyun.com/zh/ecs/user-guide/overview-of-instance-families). | Disk IOPS cannot reach the expected level or read/write speed is too slow. | [disk-perf-unexpected.md](disk-perf-unexpected.md) | dms-instancedefault |
| Performance issues | Abnormally high CPU utilization | GuestOS.CPUUtilizationTooMuch | CPU utilization is the percentage of time that the processor spends executing processes/tasks. Abnormally high CPU utilization can be caused by compute-intensive programs, configurations, or abnormal processes. | Processes run sluggishly, etc. | [cpu-high.md](cpu-high.md) | dms-instancedefault |
| Performance issues | Packet loss during network send/receive | GuestOS.NetworkPacketDrop | Packet loss means packets are lost during transmission, which may cause latency, interruptions, or the peer failing to receive expected packets. It is often caused by firewalls/security policies mistakenly dropping packets or underlying issues. | Network requests hang, network requests time out, the service does not receive expected requests, connections are unstable. | [network-packet-loss.md](network-packet-loss.md) | dms-instancedefault |
