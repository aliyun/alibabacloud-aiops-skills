# Verification Method - RDS Instances Manage

## 1. Static skill validation

Run the standard skill validator:

```bash
python3 -c 'import yaml'
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/skill-creator/scripts/quick_validate.py" .
```

Use a Python environment with PyYAML installed. Expected result: the skill name, frontmatter, and directory structure pass validation.

Verify required artifacts:

```bash
test -f SKILL.md
test -f related_apis.yaml
test "$(find references -maxdepth 1 -type f -name '*.md' | wc -l | tr -d ' ')" -eq 4
test -f evals/config/testconfig.json
test -f evals/triggering/autoGenerated/should_trigger.jsonc
test -f evals/triggering/autoGenerated/should_not_trigger.jsonc
```

Verify all 31 capability aliases appear in both the skill entrypoint and the detailed API map. Verify `related_apis.yaml` contains 30 unique API entries and does not contain `get_current_time`.

## 2. Security contract checks

Confirm tracked files contain no credential-shaped values:

```bash
rg -n 'LTAI[0-9A-Za-z]{12,}|AKIA[0-9A-Z]{16}' .
```

Expected result: no matches.

Confirm the mutation contract includes all 11 mutating aliases, explicit confirmation, read-before-write, read-after-write, no automatic retry, password redaction, and billing/downtime warnings.

## 3. Alibaba Cloud CLI readiness

```bash
command -v aliyun
aliyun version
aliyun configure set --auto-plugin-install true
aliyun plugin list
aliyun rds describe-db-instances -h
aliyun vpc describe-vpcs -h
aliyun bssopenapi describe-instance-bill -h
aliyun das get-pfs-metric-trends -h
aliyun das get-pfs-sql-summaries -h
```

Expected result:

- CLI version is `3.3.3` or newer.
- Every Action is recognized.
- A representative `--cli-dry-run` command accepts the per-command `--user-agent` option.

## 4. Credential and account verification

Use the selected profile without printing credential details:

```bash
aliyun sts get-caller-identity \
  --profile <profile> \
  --output cols=AccountId rows=AccountId
```

For the project acceptance account, expected `AccountId` is `1605970185337904`. Stop if the identity differs.

## 5. Read-only command construction

Validate representative commands with plugin global `--cli-dry-run`. Review and redact sensitive request parameters before display or retention.

Example redaction pipeline:

```bash
aliyun rds describe-db-instances \
  --biz-region-id cn-hangzhou \
  --user-agent 'AlibabaCloud-Agent-Skills/alibabacloud-rds-instances-manage/00000000000000000000000000000000' \
  --profile <profile> \
  --cli-dry-run 2>&1 |
sed -E 's/(AccessKeyId=)[^& ]+/\1<redacted>/g; s/(Signature=)[^& ]+/\1<redacted>/g; s/(SecurityToken=)[^& ]+/\1<redacted>/g'
```

Check the sanitized request contains the expected `Action`, `Version`, region, and product host, and contains no credential value. Alibaba Cloud CLI dry-run rendering may omit HTTP headers; verify the source command contains the required User-Agent and that the CLI accepts the option.

## 6. Mutating command construction

Do not invoke a live mutation during acceptance testing.

- Use plugin global `--cli-dry-run` for local construction checks of all 11 mutating Actions.
- Use `create-db-instance --dry-run true` only when valid non-secret parameters are available and a signed server-side precheck is useful. This API parameter does not create an instance.
- Never remove `--dry-run true` during acceptance testing.
- Never use a real database password in a dry-run command or fixture.
- Never execute a live `delete-db-instance` call during acceptance testing.

Confirm every sanitized dry-run request contains the expected Action and no unexpected Action. Do not treat plugin global `--cli-dry-run` as authorization, inventory, price, or business validation.

## 7. Live read-only verification

After identity verification, run only read-only calls:

```bash
aliyun rds describe-db-instances \
  --biz-region-id cn-hangzhou \
  --page-size 20 \
  --user-agent 'AlibabaCloud-Agent-Skills/alibabacloud-rds-instances-manage/{session-id}' \
  --profile <profile>

aliyun vpc describe-vpcs \
  --biz-region-id cn-hangzhou \
  --page-size 20 \
  --user-agent 'AlibabaCloud-Agent-Skills/alibabacloud-rds-instances-manage/{session-id}' \
  --profile <profile>
```

If an RDS MySQL instance exists and DAS Performance Insight (new version) is enabled, run representative `GetPfsMetricTrends` and `GetPfsSqlSummaries` calls through `--region cn-shanghai`.

Run `DescribeInstanceBill` only when the test account has billing permission. Financial permission denial is a skipped capability, not a passing result.

## 8. Result classification

Report each check as one of:

- **Passed**: executed and matched the expected contract.
- **Failed**: executed and contradicted the contract.
- **Skipped**: not executed because required permission, instance data, feature enablement, or safe parameters were unavailable.

Do not count skipped live calls as passed. Static validation and all mutation dry-run checks must pass before delivery.
