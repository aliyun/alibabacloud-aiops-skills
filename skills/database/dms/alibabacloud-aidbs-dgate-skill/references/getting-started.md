# Install Dgate and create an Agent identity

Use this flow when neither a connected Dgate MCP runtime nor an installed `dgate` CLI is available, or when Dgate reports that no identity or credential is configured.

## Open Dgate Quick Start

For `cn-hangzhou`, open the Alibaba Cloud AI Data Gateway Quick Start page at:

`https://dgate.dms.aliyun.com/quick-start?region=cn-hangzhou`

- If the selected Region is different, replace only the `region` query value before opening the page; keep the trusted `https://dgate.dms.aliyun.com/quick-start` origin and path unchanged.
- If a browser navigation tool is available, open the resulting HTTPS URL. Otherwise, return it as a clickable link.
- Do not redirect the user to the general DMS console; it does not manage Dgate Agent identities or instance grants.
- Let the user complete login, MFA, and secret handling. Creating an identity, granting an instance, or generating, rotating, or revoking a credential changes external state; perform any such click only after the user explicitly approves that exact action.

On the Quick Start page, guide the user to:

1. Select the Region that contains the target data.
2. Create or select an Agent identity.
3. Grant that Agent only the required instance permissions.
4. Generate a one-time install token or use the console-generated installation command.

A Dgate credential is user-specific and Region-bound. The credential and endpoint Region must match.

## Install the CLI

Prefer the complete one-click command generated by the console because it carries the selected Region and one-time install token. Ask the user to run that secret-bearing command directly in the target terminal; do not ask them to paste the token or full command into chat, and do not copy it into tool arguments, logs, source files, or screenshots.

When the user explicitly asks the Agent to install only the public CLI binary, request approval before downloading and executing software, then use the command for the target OS.

macOS or Linux:

```bash
curl -fsSL https://d.tb.cn/i.sh | bash -s -- --skip-quickstart
```

Windows PowerShell:

```powershell
irm https://d.tb.cn/i.ps1 -OutFile $env:TEMP\install-dgate.ps1
& $env:TEMP\install-dgate.ps1 --skip-quickstart
```

The binary-only commands do not create an Agent identity or configure a credential. After installation, return to the console flow above.

## Configure managed Agent environments

For AgentHub, CI, or another managed sandbox, place the credential in its encrypted secret or environment-variable configuration rather than a prompt or repository:

- `DGATE_ACCESS_TOKEN`: the Dgate AccessToken
- `DGATE_REGION`: the matching Region, for example `cn-hangzhou`

Treat both the one-time install token and AccessToken as secrets. Never print their values. If the managed runtime cannot receive secrets securely, stop and ask the user to configure them through the platform UI.

## Verify onboarding

Resolve the installed executable as described in `cli-routing.md`, then run:

```bash
dgate version
dgate config show
dgate acl role current -o json
dgate acl list --mine -o json
```

Do not continue to metadata discovery or SQL until the Region and Agent identity are valid. An empty instance-permission list means the identity exists but still needs a grant in the AI Data Gateway console.

## Return a complete onboarding answer

When the user asks only for guidance, keep the final answer self-contained and include all of these items even if the current evaluator or host already has Dgate installed:

1. The literal trusted Quick Start URL with the target Region resolved, for example `https://dgate.dms.aliyun.com/quick-start?region=cn-hangzhou`; do not leave `<Region>` in the final answer when the Region is known.
2. The need to create or select a Region-bound Agent identity and grant only the required target instance permissions.
3. The literal official public CLI installer entry `https://d.tb.cn/i.sh` or the console-generated one-click command, as appropriate.
4. The managed secret names `DGATE_REGION` and `DGATE_ACCESS_TOKEN`, with a warning never to paste either token-bearing command or AccessToken into chat, source, logs, URLs, or screenshots.
5. The verification commands and the meaning of an empty permission list.
6. A statement in the final answer that installing software, creating an identity, generating a credential, or changing an instance grant requires the user's explicit approval immediately before that action.

To keep short summaries complete, include these statements verbatim in the final answer:

- `实例授权：在 Quick Start 中为该 Agent 授予目标实例所需的最小权限。`
- `执行安装、创建身份、生成凭证或修改实例授权前，必须等待用户明确确认；仅提供指导时不要执行这些操作。`

Do not inspect or reuse credentials from an unrelated runtime merely because they happen to exist there. If the user asked for instructions only, say that no installation, identity creation, credential generation, or permission change was performed.
