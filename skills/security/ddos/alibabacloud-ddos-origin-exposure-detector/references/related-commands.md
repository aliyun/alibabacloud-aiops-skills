# Related CLI Commands — ddos-origin-exposure-detector

All commands use the aliyun CLI plugin mode.

| Product | CLI Command | API | Version | Description |
|---------|-------------|-----|---------|-------------|
| ddoscoo | `aliyun ddoscoo describe-instances` | DescribeInstances | 2020-01-01 | Query the list of Anti-DDoS Proxy instances (instance existence check; --page-number and --page-size are required) |
| ddoscoo | `aliyun ddoscoo describe-web-rules` | DescribeWebRules | 2020-01-01 | Query Layer-7 website forwarding rules: domain / Anti-DDoS CNAME / origin RealServer / protocol and port |
| ddoscoo | `aliyun ddoscoo describe-network-rules` | DescribeNetworkRules | 2020-01-01 | Query Layer-4 port forwarding rules: FrontendPort/BackendPort/Protocol/RealServers/**IsAutoCreate** (=true means it was auto-generated by Layer-7 website onboarding, and the origin is an Anti-DDoS forwarding cluster IP, which must be excluded from Layer-4 probing) (--instance-id, --page-number, and --page-size are required) |
| ddoscoo | `aliyun ddoscoo describe-domains` | DescribeDomains | 2020-01-01 | Query the list of configured protected domains (auxiliary) |
| Cms | `aliyun cms create-instant-site-monitor` | CreateInstantSiteMonitor | 2019-01-01 | Create a one-time site-monitor (dial-test) task |
| Cms | `aliyun cms describe-site-monitor-isp-city-list` | DescribeSiteMonitorISPCityList | 2019-01-01 | Query details of all ISP probe points (obtain city/isp codes for use with --isp-cities) |
| Cms | `aliyun cms describe-site-monitor-log` | DescribeSiteMonitorLog | 2019-01-01 | Query the per-probe-point detail log of a one-time site-monitor task (parse IP / status code / response time) |

## Key Parameter Quick Reference

### ddoscoo describe-web-rules
- `--region` : `cn-hangzhou` (Chinese mainland) / `ap-southeast-1` (outside Chinese mainland)
- `--domain` : specify a domain (optional; only use it when narrowing down to a single domain)
- **`--instance-ids` : [MUST] do NOT use it to filter** — testing shows this filter causes large-scale under-collection (35 real domains exist within the region, but querying instance by instance with instance-ids returned only 7). This API returns all website rules of the region by region, so querying directly by region is the most complete.
- `--page-size` (1~10) / `--page-number` : [MUST] first read `TotalCount` from page 1, then fetch all pages by `ceil(TotalCount/10)`, and verify the cumulative count == TotalCount
- Returns: `WebRules[].Domain`, `WebRules[].Cname`, `WebRules[].RealServers[].RealServer`, `WebRules[].ProxyTypes[]`, `TotalCount`

### cms create-instant-site-monitor
- `--address` (required) : the probe target, **distinguished by task-type**: for DNS provide a domain (`www.example.com`); for HTTP provide a URL (`http://1.2.3.4:443`); **for TCP/UDP provide only the IP (`1.2.3.4`, without a port! including a port raises `illegal port`)**
- `--task-type` (required) : `HTTP` / `PING` / `TCP` / `UDP` / `DNS`
- `--task-name` (required) : task name (4~100 characters)
- `--random-isp-city` : number of random probe points (mutually exclusive with --isp-cities)
- `--isp-cities` : precisely specify probe points as a JSONArray, e.g. `[{"city":"546","isp":"465","type":"IDC"}]`; type=IDC/LASTMILE. Once this is set, random-isp-city is ineffective
- `--options-json` : protocol extension options (**wrap the entire JSON in single quotes to avoid escaping errors**):
  - HTTP binding the Host header → `'{"header":"Host: www.example.com","time_out":5000}'` (**no `host` key**; the Host goes through the `header` field)
  - TCP/UDP specifying a port → `'{"port":443,"time_out":5000}'`
- `--agent-group` : `PC` (fixed-line) / `MOBILE` (mobile), default PC
- Returns: `CreateResultList[0].TaskId` (TaskId is at this path, not Data.TaskId); use describe-site-monitor-log to retrieve results

### cms describe-site-monitor-log
- `--task-ids` (required) : the probe task ID, **pass only one TaskId at a time and query them one by one** (the CLI parses comma-separated multiple IDs unreliably and will raise `invalid character`)
- `--metric-name` : currently only `ProbeLog` is supported
- `--isp` / `--city` : filter by ISP / city
- `--filter` : filter expression (e.g. `TotalTime>100`)
- `--start-time` / `--end-time` / `--length` (1~1440) / `--next-token`
- Returns: `Data` (per-probe-point probe log, including the actually resolved IP, HTTP status code, and response time)

## Local Probing Commands (ProbeMode=local, or a fallback when the cloud dial-test service is not enabled)

Local probing is initiated directly from the machine running the Skill, requires no cloud service to be enabled, and has zero cost; the limitation is that it provides only a single network egress viewpoint.

### S1 — DNS resolution (`dig`)
```bash
dig +short www.example.com          # final resolved IP, compare against the origin IP to determine S1
dig www.example.com CNAME +short    # check whether the CNAME falls under the Anti-DDoS signature domain *.aliyunddos*.com
```
- Determination: if the resolution result hits the origin IP and does not go through the Anti-DDoS CNAME → S1 hit.

### S2(a) — Layer-7 domain onboarding, direct HTTP connection (`curl --resolve` binding the Host)
```bash
# HTTP
curl -sS -o /dev/null -w '%{http_code}\n' --connect-timeout 5 --max-time 8 \
  --resolve "www.example.com:<port>:<origin-ip>" "http://www.example.com:<port>/"
# HTTPS (add -k when the certificate does not match; only checks connectivity and status code)
curl -sS -k -o /dev/null -w '%{http_code}\n' --connect-timeout 5 --max-time 8 \
  --resolve "www.example.com:<port>:<origin-ip>" "https://www.example.com:<port>/"
```
- `--resolve <domain>:<port>:<origin-ip>`: forces the domain to resolve to the origin IP while preserving the correct Host header (equivalent to the host in the cloud dial-test's options-json).
- Determination: returns 2xx/3xx → S2 hit; 4xx/5xx or connection failure → do not determine S2 (mark as suspected partially reachable).

### S2(b) — Layer-4 port onboarding (choose TCP or UDP based on the Protocol field)

**Protocol=tcp** — `nc` probing the TCP handshake:
```bash
nc -z -w 5 <origin-ip> <port> && echo "TCP OPEN" || echo "TCP CLOSED/FILTERED"
# fallback when nc is unavailable:
curl -sS -v --connect-timeout 5 "telnet://<origin-ip>:<port>" 2>&1 | grep -i connected
```
- Determination: TCP handshake succeeds (OPEN/connected) → S2 hit; failure → not hit.

**Protocol=udp** — `nc -u` probing the UDP port:
```bash
nc -zu -w 5 <origin-ip> <port> && echo "UDP OPEN/NO-REJECT" || echo "UDP CLOSED/FILTERED"
```
- Determination: no ICMP port unreachable received (OPEN/NO-REJECT) → S2 hit; an explicit closed response returned → not hit.
- Note: UDP has no handshake, so "reachable" only means the port was not explicitly rejected, and the conclusion's reliability is lower than TCP. The report must note "the UDP probe conclusion is for reference only; it is recommended to confirm with the business".

### When the origin is a domain (RsType=1), resolve locally first
```bash
dig +short <origin-domain>          # resolve to an IP first, then perform S2 probing
```
